## 二、轨迹质量评估数据怎么读（回答"质量咋样、有没有问题"）

以 0033 最新 run（2baeba10，ATE 4.83m）为例：
- **ATE RMSE 4.83m / 轨迹 760m ≈ 0.6% 漂移**——对手工数据适配（合成角速度、无硬件时间同步）是合理水平；误差曲线呈"两端高中间低"形态，符合 LIO 漂移特征（无回环校正，误差单向累积后部分回归）。
- **RPE 0.5s=0.26m、1s=0.52m、2s=1.03m**，随间隔线性增长且配对数充足——局部一致性良好，说明内参/外参/时间同步基本正确；若有外参或同步错误，RPE 会呈现非线性跳变。
- **结论：评估流程真实可信，数值可用**。注意两点口径：①参考是 GPS/INS 而非官方真值；②两次 0033 实验 ATE 差异大（23.9m vs 4.83m）说明对回放速率/配置敏感——这正是实验管理+对比功能存在的意义。

## 三、需求对照评审

**业务需求**：目标用户操作流（选序列→重建→查看→评估→对比→导出）已全链路可用；缺口是"逐帧回放"和"报告 PDF"。**达标 ~80%。**

**功能需求**（8 模块）：①数据集管理——已实现（列表/导入校验/体检报告），缺自动嗅探目录；②建图任务——已实现（真实 FAST-LIO2、停止、日志），缺进度百分比；③三维建图——渲染核心可用，缺逐帧回放/跟随视角/着色切换/LOD；④评估——ATE/RPE/曲线/对比已实现，缺旋转分量 RPE 与官方真值接入；⑤配置+实验管理——已实现（校验/预设/历史/对比）；⑥报告——JSON/CSV/HTML 已实现，PDF 未实现；⑦闭环——V2.0 未实现（如实标注）；⑧监控日志——已实现（真实 /proc 数据 + 可检索日志）。

**非功能需求**：性能（鲲鹏 96 核富余，逐帧 200ms 是当前配置下瓶颈，需调参或接受慢放）；可复现性（配置快照入库 ✓）；安全（内网无鉴权，联外网前必须加）；可维护性（单文件前端 900+ 行已到上限，见下）；兼容（Chrome/Edge 实测，WebGL 必需）。

## 四、前端框架建议：V1.1 起迁移 **Vue3 + Three.js(Potree) + ECharts**（同意提案方向）

理由：
1. **手写渲染器边际成本已现**：逐帧回放、相机跟随、LOD、拾取——每项在原生 WebGL 上都是周级工作量，Three.js 有现成方案；3000 万点用 **Potree/3DTiles 八叉树 LOD** 才是正解（WebGL 抽样 150 万点只是过渡）。
2. **页面数会继续涨**（回放器、闭环对比、报告中心），Vue3 的组件化/响应式能把 900 行单文件拆成可维护组件；Vite 构建 + 内网产物部署（纯静态 dist，不引入运行时 CDN 依赖）。
3. ECharts 承接误差曲线/多实验对比图，替代手绘 canvas。
4. **软著影响可控**：自研边界在业务代码（组件、状态管理、评估可视化逻辑），GPL/许可风险为零（Three.js MIT、ECharts Apache-2.0、Vue MIT）；现有手写渲染器保留为"轻量模式"或对比基线。

后端（FastAPI + SQLite + 容器流水线）**不需要推翻**，仅需增量：WebSocket 推送任务进度、实验对比聚合接口、真值文件管理。

## 五、V1.1 排期建议（按价值排序）

1. 前端迁移 Vue3 + Potree LOD（解渲染上限与可维护性，一次投入两收益）
2. 逐帧回放 + 相机跟随（业务演示价值最高）
3. ATE/RPE 对接 KITTI Odometry 官方真值序列（00~10，评估口径升级）
4. 实验对比聚合接口 + PDF 报告（reportlab）
5. WebSocket 任务进度推送
